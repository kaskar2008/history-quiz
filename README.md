# Квиз по мировой истории

Мобильный веб-квиз по мировой истории: 10 уровней сложности, 1183 вопроса,
режимы «Жизни» и «Бог», очки, звания, звёзды, серии и достижения. Прогресс и
рекорды сохраняются в `localStorage`. Бэкенд не требуется.

## 1. Запуск проекта

Требуется Node.js 18+ (проверено на Node 22).

```bash
npm install       # установить зависимости
npm run dev       # запустить дев-сервер (http://localhost:5173)
npm run build     # проверить типы и собрать production-сборку в docs/
npm run preview   # локально просмотреть production-сборку
```

Сборка кладётся в `docs/` (настроено в `vite.config.ts` через `build.outDir`) —
это позволяет опубликовать приложение через GitHub Pages прямо из папки
`docs` в основной ветке репозитория, без отдельной ветки `gh-pages`. Если
сайт будет открываться не в корне домена, а по пути вида
`username.github.io/repo-name/`, дополнительно понадобится указать
`base: '/repo-name/'` в `vite.config.ts`.

Полезные команды при разработке:

```bash
npm run test              # прогнать все тесты (vitest run)
npm run test:watch        # тесты в watch-режиме
npm run typecheck         # только проверка типов (tsc -b)
npm run validate:questions  # валидация базы вопросов
npm run lint               # oxlint
```

## 2. Технологический стек

- React 19 + TypeScript, сборка на Vite.
- Обычный CSS + CSS Modules для компонентов и экранов, без UI-фреймворков.
- Vitest + Testing Library для тестов.
- `localStorage` для хранения прогресса, без бэкенда и авторизации.

## 3. Архитектура

```text
src/
  components/     переиспользуемые UI-компоненты (кнопки, варианты ответа,
                   индикаторы жизней/серии/звёзд, нижняя панель, тосты)
  screens/        экраны приложения (Home, ModeSelection, LevelMap, Loading,
                   Question, LevelResult, GameResult, Statistics, Achievements)
  hooks/
    useGame.ts    связывает reducer с загрузкой вопросов и сохранением прогресса
  services/
    questionLoader.ts     динамическая загрузка уровней, отбор и сортировка 30 вопросов
    storageService.ts     безопасное чтение/запись localStorage, статистика
    sessionService.ts     сохранение/восстановление активной сессии (для reload)
    scoringService.ts     чистые функции подсчёта очков, серий, звёзд, званий
    achievementService.ts проверка условий достижений
    recordService.ts      ключ рекорда и определение нового рекорда
  game/
    types.ts      типы игрового состояния, режимов, фильтров, прогресса,
                   а также (де)сериализация сессии для восстановления
    config.ts     все игровые константы (очки, бонусы, звания, достижения)
    reducer.ts    конечный автомат экрана игры (см. ниже)
  data/
    types.ts              типы вопроса и справочников
    dictionaries/          countries.json, regions.json, periods.json, topics.json
    questions/
      index.json           метаданные и пути к файлам уровней
      level-01.json..level-10.json  по 32 вопроса на уровень
  styles/
    global.css    сброс стилей, переменные темы, safe-area, 100dvh, focus-visible
scripts/
  validateQuestions.ts  скрипт и переиспользуемая функция валидации базы
```

Игровая логика полностью отделена от интерфейса: `game/reducer.ts` реализует
конечный автомат со стадиями

```text
home → mode-selection → level-map → loading → question → answer-result
     → level-result → game-result
```

Экраны — простые презентационные компоненты, которые получают состояние и
колбэки из `useGame()` и не содержат игровой логики. Выбор ответа блокируется
сразу после клика (`isAnswerLocked`), поэтому повторная обработка одного и
того же ответа невозможна.

## 4. Хранение прогресса

`storageService.ts` хранит в `localStorage` под ключом `history-quiz:progress:v1`
объект `StoredProgress`: попытки (обрезаются до последних 100), агрегированную
статистику отдельно по режимам «Жизни» и «Бог», лучшие результаты и звёзды по
уровням отдельно по режимам, список полученных достижений и рекорды по ключу
`режим + область + страны + регионы + периоды + темы` (массивы сортируются
перед формированием ключа). Конкретные ответы пользователя не сохраняются.

Чтение из `localStorage` полностью безопасно: при отсутствии ключа,
повреждённом JSON, неожиданной структуре данных или несовпадающей версии
приложение не падает, а возвращает пустой прогресс.

Лучший результат и звёзды по уровню сохраняются сразу при завершении этого
уровня — они не теряются, даже если игрок затем выйдет из игры досрочно.
А вот сводка по попытке целиком (очки, точность, статистика режима, рекорд)
записывается только при настоящем завершении прохождения — победой,
поражением по правилам режима «Жизни» или полным прохождением всех 10
уровней. Досрочный выход через кнопку выхода не создаёт запись в статистике
попыток — интерфейс явно предупреждает об этом перед выходом.

### Восстановление сессии после перезагрузки страницы

Пока попытка активна (экраны карты уровней, загрузки, вопроса, ответа или
результата уровня), `sessionService.ts` отдельно сохраняет в `localStorage`
(ключ `history-quiz:session:v1`) снимок текущей сессии: режим, фильтры,
уровень, сам набор из 30 выбранных вопросов в их итоговом порядке, индекс
текущего вопроса, очки, серию, счётчики ошибок, результаты уже пройденных
уровней и дедлайн таймера текущего вопроса. При перезагрузке страницы это
состояние читается ещё до первой отрисовки и игра продолжается ровно с того
же места — включая оставшееся время на текущий вопрос: таймер хранится как
абсолютный момент истечения (`questionDeadlineAt`), а не как секундомер, и
на входе просто пересчитывается «сколько осталось» через разницу с текущим
временем. Если этот момент уже в прошлом (например, вкладка была закрыта
дольше 20 секунд), вопрос без выбранного варианта сразу засчитывается как
просроченный — так же, как истечение таймера в реальном времени.

Снимок сессии удаляется, как только попытка перестаёт быть «активной»:
на главном экране, при выборе режима и по завершении прохождения (там
результат уже сохранён в `StoredProgress`, повторное восстановление того же
экрана могло бы задвоить статистику). Подтверждённый досрочный выход тоже
удаляет снимок — возобновлять уже нечего.

## 5. Загрузка вопросов

Вся база вопросов не загружается при старте. `src/data/questions/index.json`
содержит только метаданные по уровням; сами вопросы уровня подгружаются через
`import.meta.glob` (ленивая динамическая загрузка, каждый уровень — отдельный
JS-чанк, что видно в выводе `npm run build`). Пока игрок проходит текущий
уровень, следующий предзагружается в фоне (`prefetchLevelQuestions`).

Из пула вопросов уровня (32 вопроса) на прохождение случайно выбираются 30
уникальных без повторов (`selectQuestionsForLevel` + `shuffle`, чистые функции
с инъекцией источника случайности — это делает их детерминированными в тестах).

Каждый вопрос несёт отдельное поле `difficulty` (число), не зависящее от
`level`. После случайного отбора 30 вопросов они сортируются по `difficulty`
по возрастанию, поэтому прохождение всегда идёт от более лёгких вопросов к
более сложным, даже если конкретный набор вопросов каждый раз разный.
Значения `difficulty` в текущей базе расставлены с шагом 10 (10, 20, 30…),
чтобы новые вопросы можно было свободно вставлять между существующими, не
переприсваивая сложность всем остальным. У нескольких вопросов внутри уровня
`difficulty` может совпадать — важно лишь, чтобы на уровень было не меньше
30 уникальных значений (это же проверяет `validate:questions`), иначе большая
случайная выборка даст длинные участки с вопросами «в произвольном порядке
сложности».

Варианты ответа при показе вопроса перемешиваются на экране (`shuffle` из
`questionLoader`, пересчитывается только при смене вопроса), так что позиция
правильного ответа не заучивается при повторных прохождениях — в самих JSON
файлах порядок вариантов и `correctOptionId` остаются как есть.

## 6. Инструкция по добавлению вопросов

1. Откройте `src/data/questions/level-XX.json` нужного уровня.
2. Добавьте объект вопроса по образцу:

```json
{
  "id": "h01-033",
  "level": 1,
  "difficulty": 325,
  "question": "Текст вопроса (до ~160 символов)",
  "details": null,
  "options": [
    { "id": "a", "text": "Вариант А" },
    { "id": "b", "text": "Вариант Б" },
    { "id": "c", "text": "Вариант В" },
    { "id": "d", "text": "Вариант Г" }
  ],
  "correctOptionId": "a",
  "explanation": "1-3 коротких предложения, объясняющих правильный ответ.",
  "countries": ["egypt"],
  "region": "africa",
  "period": "ancient",
  "topics": ["culture"],
  "yearFrom": -3000,
  "yearTo": -2900
}
```

- `id` — уникальный по всей базе, стабильный (не меняйте его при правках).
- `level` должен совпадать с номером файла.
- `difficulty` — число, определяющее место вопроса в очерёдности сложности
  внутри уровня (см. раздел 5). Для новых вопросов удобно брать значение
  между двумя соседними по сложности существующими вопросами (например,
  вставить с `difficulty: 325` между вопросами 320 и 330) — тогда не нужно
  ничего переприсваивать. Совпадения допустимы, но на уровень должно
  оставаться минимум 30 уникальных значений.
- Ровно 4 варианта с уникальными `id` и текстами; `correctOptionId` должен
  совпадать с одним из `options[].id`.
- `region` — один из `src/data/dictionaries/regions.json`.
- `period` — один из `src/data/dictionaries/periods.json`.
- `topics` — один или несколько из `src/data/dictionaries/topics.json`.
- `countries` — один или несколько slug'ов из `src/data/dictionaries/countries.json`.
  Если нужен новый slug (страна/историческое государство), добавьте запись
  `{ "id": "...", "label": "..." }` в `countries.json`.
- `details` — `null`, если контекст не нужен, иначе краткая строка,
  не раскрывающая ответ (кнопка «i» появится автоматически).
- При необходимости обновите `questionCount` соответствующего уровня в
  `src/data/questions/index.json`.

3. Обновите `questionCount` уровня в `index.json`, если поменялось число
   вопросов в файле.
4. Запустите `npm run validate:questions` — скрипт проверит уникальность id,
   соответствие уровня файлу, обязательные поля (включая `difficulty`), ровно
   4 уникальных варианта, наличие `correctOptionId` среди вариантов,
   допустимые категории, диапазон лет, тип `details`, минимум 30 вопросов и
   минимум 30 уникальных значений `difficulty` на уровень, отсутствие полных
   дублей вопросов и корректность JSON.
5. Запустите `npm run test` и `npm run build`, чтобы убедиться, что ничего не
   сломалось.

## 7. Список функций

- 10 уровней сложности с пулом от 100 до 232 вопросов на уровень (1183 вопроса
  всего), на каждое прохождение уровня случайно выбираются 30 уникальных и
  выстраиваются по возрастанию `difficulty` — от более лёгких к более сложным.
  База легко расширяется: новые вопросы просто добавляются в файл уровня со
  своим значением `difficulty`, без изменения кода.
- Вопросы охватывают все континенты и эпохи: от доистории и древнего мира до
  новейшего времени, с акцентом на разнообразие регионов (Африка, Азия,
  Америка, Ближний Восток, Океания, Европа), а не только на Европу.
- На каждый вопрос даётся 20 секунд; если время истекло, вопрос засчитывается
  как неверный (без выбранного варианта) и показывается пояснение с пометкой
  «Время вышло» — так же, как при обычном неверном ответе.
- Варианты ответа перемешиваются при каждом показе вопроса, чтобы нельзя было
  запомнить положение правильного ответа.
- Пояснение после каждого ответа; кнопка «i» с дополнительным контекстом
  показывается только при заполненном `details` и открывается как нижняя
  панель с закрытием по кнопке и Escape и возвратом фокуса.
- Кнопку выхода можно нажать в любой момент активной игры (экраны загрузки,
  вопроса и результата уровня). Перед выходом показывается предупреждение,
  что текущая попытка не будет засчитана в статистику и рекорды — уже
  пройденные уровни и достижения при этом остаются сохранёнными.
- Два режима игры: «Жизни» (5 ошибок разрешено, 6-я завершает попытку) и
  «Бог» (без ограничения ошибок).
- Очки: 100 за верный ответ, бонусы серии (+10/+20/+30 в зависимости от
  длины серии), +300 за уровень, +500 дополнительно за уровень без ошибок.
- Звания (от «Новичка» до «Хранителя времени»), 1-3 звезды за уровень по
  точности, отображение текущей и максимальной серии.
- 7 достижений с уведомлением о разблокировке.
- Раздельная статистика, рекорды и лучшие результаты по уровням для каждого
  режима; рекорд учитывает область (страны/регионы/периоды/темы) с ключом,
  устойчивым к порядку элементов.
- Прогресс переживает перезагрузку страницы; хранится история последних 100
  попыток без сохранения конкретных ответов.
- Активная попытка тоже переживает перезагрузку страницы: уровень, набор
  вопросов и их порядок, очки, серия, счётчики ошибок, результаты пройденных
  уровней и оставшееся время на текущий вопрос восстанавливаются один в один.
- Архитектура готова к будущей фильтрации по странам, регионам, периодам и
  темам (`QuizFilters`, `filterQuestions`) без изменений игровой логики.
- Mobile-first интерфейс: одна колонка, крупные (44×44 px и больше) зоны
  нажатия, нижняя кнопка «Далее», защита от двойного нажатия после ответа,
  видимый фокус, поддержка `prefers-reduced-motion`, `100dvh` с fallback,
  адаптация для планшетов и десктопа с ограничением ширины контента.

## 9. Ручная проверка интерфейса

Автоматически проверено (headless-браузером, вручную из этого окружения, без
постоянной зависимости в проекте) на ширинах 320, 390 и 1280 px: главный
экран, выбор режима, карта уровней, экран вопроса с таймером и кнопкой
выхода, диалог подтверждения выхода, экран ответа с пояснением (включая
истечение времени), нижняя панель «Подробнее о вопросе», экран результата
уровня, перемешивание вариантов ответа между заходами — без горизонтальной
прокрутки и ошибок в консоли.

Отдельно проверено восстановление сессии: перезагрузка страницы посреди
уровня возвращает тот же вопрос, тот же прогресс (например, «3 / 30»), тот же
счёт и таймер, продолжающий отсчёт с того же значения (а не сброшенный на 20
секунд); перезагрузка на главном экране не подхватывает никакой устаревшей
сессии; а если дедлайн вопроса уже истёк за время, пока страница была закрыта,
вопрос сразу засчитывается как просроченный при восстановлении.

Рекомендуется дополнительно вручную проверить ширины 360, 430 и 768 px и
кейсы с длинным вопросом/ответом/пояснением на реальных устройствах.
